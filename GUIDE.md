# Гайд: как открыть, проверить и сдать проект «ОРБИТА»

Сделано по двум приложенным методичкам: итоговая работа «Полноценный сайт на HTML, CSS и JavaScript» и «Создание Git-репозитория и загрузка сайта».

## 1. Что именно готово

Проект — оригинальный сайт-атлас планет, написанный без фреймворков. Внутри три HTML-страницы, отдельный CSS, три JS-файла и локальные иллюстрации. Основные требования выполнены; добавлены бонусы: поиск, фильтры, избранное, модальное окно, пауза слайдера. Вам не требуется придумывать сайт с нуля.

**Важно:** GitHub-репозиторий и адрес GitHub Pages принадлежат вашему аккаунту. Без вашего доступа к GitHub нельзя безопасно опубликовать проект от вашего имени. Поэтому ниже даны точные команды для публикации.

## 2. Распакуйте проект

1. Скачайте ZIP из ответа.
2. Распакуйте, например, в папку `ORBITA-site` в «Документах».
3. Убедитесь, что внутри **сразу видны `index.html`, `auth.html`, `cabinet.html`**. Не загружайте на GitHub ещё один ZIP — выкладывать нужно сами файлы.
4. Откройте папку в VS Code: `File → Open Folder`.

## 3. Откройте сайт на компьютере

### Вариант A — через Python

Откройте терминал **в папке, где лежит `index.html`**:

```bash
python -m http.server 5500
```

Если написано, что команда `python` не найдена, попробуйте:

```bash
python3 -m http.server 5500
```

В браузере перейдите по ссылке: **http://localhost:5500**.

Чтобы остановить сервер, нажмите **Ctrl+C** в терминале.

### Вариант B — через VS Code

Установите расширение `Live Server`, откройте `index.html`, нажмите **Go Live** и дождитесь открытия вкладки браузера.

**Не рекомендуется проверять регистрацию через двойной клик по `index.html`:** в режиме `file://` некоторые браузеры ограничивают `localStorage` и Web Crypto. На localhost обе технологии доступны в поддерживаемых современных браузерах.

## 5. Полный сценарий проверки перед сдачей

### Слайдер и материалы

1. На `index.html` найдите блок «Миры, которые вдохновляют».
2. Нажмите стрелку вправо: **Земля → Сатурн**. Нажмите третью точку: **Нептун**.
3. Если не наведена мышь и устройство не просит уменьшить анимации, слайдер меняется самостоятельно приблизительно раз в 5 секунд.
4. В разделе «Атлас планет» видно 8 карточек.
5. Нажмите «Каменистые»: останется 4 карточки. «Газовые»: 2. «Ледяные»: 2.
6. В поле поиска напишите `марс`: должна остаться карточка «Марс» (при фильтре «Все планеты»).
7. Нажмите «Подробнее» на любой карточке: появятся описание, примерное расстояние от Солнца и продолжительность года. Закройте диалог крестиком или клавишей Escape.

### Регистрация и вход

1. Откройте `cabinet.html` без входа: должно появиться **сообщение об отказе**.
2. Откройте `auth.html#register`. Попробуйте отправить пустую форму: появятся сообщения под полями.
3. Укажите выдуманное имя, синтетический email наподобие `student@example.test`, пароль из 6+ символов и несовпадающее подтверждение: появится ошибка.
4. Исправьте подтверждение, отметьте согласие, нажмите «Создать аккаунт».
5. Вас переведёт в кабинет: имя, email и дата регистрации должны быть заполнены.
6. В шапке вместо «Войти» появятся имя и кнопка «Выйти».
7. На главной нажмите сердечко у одной или нескольких планет. В кабинете проверьте список избранного.
8. Обновите страницу: данные должны сохраниться. Удалите одну планету из избранного.
9. Нажмите «Выйти», убедитесь, что кабинет снова закрыт.
10. Попробуйте зарегистрировать **тот же email**: получите сообщение о существующем аккаунте.
11. На вкладке «Вход» сначала введите неверный пароль — будет ошибка. Затем верный — кабинет откроется снова.

### Адаптивность

1. В Chrome/Edge нажмите `F12` → «Toggle device toolbar» (значок телефона) или `Ctrl+Shift+M` / `Cmd+Shift+M`.
2. Проверьте ширину **1440 px** — 4 колонки карточек.
3. Проверьте ширину **768 px** — 2 колонки.
4. Проверьте ширину **390 px** — 1 колонка и бургер-меню. Меню должно открываться и закрываться.
5. Убедитесь, что страница не прокручивается горизонтально.

## 6. Как опубликовать на GitHub

**Для этого проекта репозиторий уже создан:** https://github.com/ga223-tech/site. При повторной загрузке файлы должны лежать в корне ветки `main`.

### 6.1 Установите Git

Скачайте Git с **https://git-scm.com/downloads**, установите и в новом терминале проверьте:

```bash
git --version
```

Создайте аккаунт на **https://github.com/**, если его нет.

### 6.2 Настройте автора коммитов

Подставьте **свои реальные имя и адрес** (адрес может быть GitHub noreply):

```bash
git config --global user.name "Ваше Имя"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
```

Если Git уже настроен, этот шаг можно пропустить.

### 6.3 Создайте пустой репозиторий на GitHub

1. Откройте **https://github.com/new**.
2. В поле **Repository name** введите `site`.
3. Выберите **Public**.
4. Не ставьте галочки **Add a README**, **Add .gitignore** и **Choose a license** — эти файлы уже есть локально (README, .gitignore).
5. Нажмите **Create repository**.

### 6.4 Загрузите файлы

В терминале перейдите **внутрь папки `ORBITA-site`**. Перед выполнением убедитесь, что команда `ls` (или `dir` в Windows) показывает `index.html`.

```bash
git init
git branch -M main
git add .
git commit -m "feat: create ORBITA solar system atlas"
git remote add origin https://github.com/ga223-tech/site.git
git push -u origin main
```

**Замените `ga223-tech` на свой username GitHub.** Возможно, GitHub попросит открыть браузер и подтвердить вход. Не передавайте пароль аккаунта посторонним и не сохраняйте персональные токены в проекте.

В разделе **Code** репозитория должны быть видны `index.html`, папки `css`, `js`, `img`, README и другие файлы, а **не архив**.

### 6.5 Включите GitHub Pages

1. Откройте свой репозиторий на GitHub.
2. Перейдите в **Settings → Pages**.
3. В разделе **Build and deployment** выберите **Source: Deploy from a branch**.
4. Выберите ветку **main** и папку **/ (root)**, нажмите **Save**.
5. После завершения публикации GitHub покажет URL вида:

   `https://ga223-tech.github.io/site/`

6. Откройте URL и проверьте главную, регистрацию и кабинет именно по публичной ссылке.
7. Вернитесь в `README.md`, впишите свою публичную ссылку и данные автора, затем отправьте обновление:

```bash
git add README.md
git commit -m "docs: add author and GitHub Pages URL"
git push
```

### 6.6 Как отправлять исправления позже

```bash
git add .
git commit -m "fix: improve layout and functionality"
git push
```

Не включайте в репозиторий архивы, пароли и токены. `.gitignore` уже исключает обычные мусорные файлы и `.zip`.

## 8. Пример речи для защиты (3–5 минут)

> Мой проект называется «ОРБИТА». Это интерактивный атлас восьми планет Солнечной системы. Я выбрал узкую тему, чтобы пользователю было удобно находить информацию и сохранять интересные материалы.
>
> Сайт создан на HTML, CSS и JavaScript без фреймворков. Я разделил его на три страницы: главную, страницу входа и регистрации и личный кабинет. Для оформления использовал CSS-переменные, Flexbox, Grid и медиазапросы — поэтому сайт подстраивается под телефон, планшет и компьютер.
>
> На главной работает JavaScript-слайдер из трёх слайдов с кнопками, точками и автопрокруткой. Все восемь карточек создаются не вручную, а из массива объектов в файле `data.js`, с помощью `map()` и `join()`. Работают поиск, фильтрация, кнопка «Подробнее» и добавление в избранное.
>

>
> В личном кабинете показываются имя, адрес, дата регистрации и сохранённые планеты. Без входа доступ к кабинету закрыт. Данные сохраняются после перезагрузки, а кнопка «Выйти» удаляет сеанс.
>
> Код опубликован в GitHub-репозитории, а демонстрация доступна через GitHub Pages. При проверке я прошёл сценарии регистрации, входа, выхода, работы с каталогом и адаптивного меню.

Последнюю фразу о GitHub произносите **только после реальной публикации**.

## 9. Частые ошибки и решения

| Проблема | Что сделать |
|---|---|
| Сайт открывается, но регистрация не работает | Используйте `http://localhost:5500` вместо `file://` и проверьте наличие Web Crypto API. |
| Пользователь исчез после очистки браузера | Ожидаемо: учебные данные хранятся в localStorage, не на сервере. |
| Забыли пароль тестового аккаунта | Очистите данные сайта для localhost или используйте новый email. |
| Git пишет `not a git repository` | В терминале перейдите в папку с `index.html`, затем выполните `git init`. |
| `remote origin already exists` | Используйте `git remote set-url origin https://github.com/ga223-tech/site.git`. |
| `rejected` при push | Убедитесь, что удалённый репозиторий был создан пустым. Не используйте `--force` без понимания последствий. |
| GitHub Pages показывает 404 | Проверьте `main`, `/ (root)`, наличие `index.html` в корне и статус публикации в Settings → Pages. |
| Иконки/картинки не видны на Pages | Проверьте, что папка `img/` загружена и регистр букв в путях совпадает. |
| Не работают шрифты без интернета | Сайт использует системные резервные шрифты; остальная функциональность от Google Fonts не зависит. |

## 11. Что именно проверено автоматически

При сборке проекта выполнены **19 smoke/UI-проверок**, все прошли: три слайда и автопрокрутка, восемь карточек, фильтры, поиск, диалог, отказ без входа, валидация, регистрация, отображение профиля, добавление/удаление избранного, выход/повторный вход, мобильное меню, отсутствие горизонтальной прокрутки на пяти ширинах, колонки сетки на трёх ширинах.

**Ограничение проверки:** в среде сборки Chromium запрещает сетевую и файловую навигацию административной политикой, поэтому тесты использовали `page.set_content()` с встроенными локальными файлами и тестовой имитацией `localStorage`/Web Crypto. Скрипт оставлен в `tests/test_site.py`. Он проверяет большую часть пользовательской логики, но не является полноценным тестом опубликованного сайта. Перед сдачей обязательно проверьте localhost и GitHub Pages в вашем браузере.
